# 規格修訂補遺（2026-10-22）—俯視／等角 2.5D 美術基準

**[已確認]** 俯視／等角視角、跟隨鏡頭、可延伸場景；AI 協助製作風格一致的角色與環境素材。正式風格細節及投影規則仍為**[待決]**。本節優先於只將場景視為固定背景的舊描述。

## 空間一致性
- 場景、角色、障礙及互動物件共用一致的視角、透視傾斜、光源方向與尺度邏輯。角色腳底／接地點需對齊世界座標；互動區不得只依生成圖片像素猜測。
- **[待決]** 最終採正交俯視、斜俯視或等角投影。原型可選一種快速驗證，但不可寫成正式定案。
- 按需要分層：遠景、背景建築、中景、可行走地面、互動物件、角色、前景遮擋。不是每張圖都必須拆層。
- 前景不可永久遮住角色與重要互動提示。前後排序規則**[待決]**，原型可採簡單排序並記錄限制。
- 視差用於視覺深度，不能造成地面、碰撞與角色位置脫節；幅度保守，考慮低動態替代。

## AI 素材一致性流程
1. 建立可重用的場景／角色文字規格：視角、比例、輪廓、材質、光源、色彩、年代與禁止項目。
2. 同批素材共用參考條件與描述，記錄提示詞、工具、生成日期、來源及條款狀態。
3. 優先生成無文字背景與獨立元素；UI、符號、提示由 HTML/CSS 或遊戲邏輯呈現。
4. 檢查視角漂移、比例不一致、浮水印、商標、錯誤物件及碰撞位置不符。AI 輸出不自動通過驗收。
5. 不要求手工繪圖、手動修圖或完整 3D 模型；可用裁切、透明素材、CSS 疊層、佔位圖或重新生成替代。

## 手機效能
- 壓縮圖片、限制高解析圖層、粒子與動畫更新量；避免昂貴即時光影。
- 角色、互動提示及可通行區域在小螢幕上易辨認；UI 避開安全區與瀏覽器工具列，觸控目標寬裕。
- 不只靠顏色傳達狀態；重要互動需有文字、形狀或動畫替代提示。
- **[待決]** 解析度、素材格式、動畫影格、角色方向數、遮擋演算法及效能目標，待目標裝置原型測試後決定。

### 0.1 本文件要解決的問題

本專案由只有手機或平板、零預算、沒有專業修圖與程式背景的擁有者製作。美術流程必須做到：

## 1. 整體美術風格

### 1.1 正式風格定義

**低飽和、具材質感的敘事探索插畫；電影感科幻奇幻遺跡；手繪概念藝術與可信環境設計融合；以俯視／等角構圖、可延伸的地面與環境圖層、清楚的角色輪廓及克制的霧氣、微光和粒子，營造安靜、古老、可探索的世界。素材可先以單張佔位圖驗證玩法，再逐步補足分層與動態；不得假設所有場景永遠是固定背景。**

視覺關鍵字：

- 沉靜、耐看、克制、潮濕、風化、失落但非完全荒廢。
- 大尺度環境與清楚焦點；環境先於角色表演。
- 古代工程遺跡而非純魔法神殿。
- 材質具有使用痕跡，結構有合理支撐與維護邏輯。
- 神秘感來自不完整資料、重複符號、磨損和異常回應，不靠滿畫面魔法光柱。
- 允許畫面具有藝術化簡化，但不犧牲可探索物件的可讀性。

### 1.2 禁止的風格漂移

避免下列方向成為主要美術語言：

- 高飽和糖果色、霓虹賽博龐克、滿屏藍紫發光線。
- 高反光塑膠感 3D、過度鏡面材質、遊戲商城宣傳圖式構圖。
- 大量動漫式誇張眼睛、偶像服裝、華麗盔甲或不符合角色職業的飾品。
- 蒸汽龐克齒輪堆滿每個角落，或把所有古代科技畫成齒輪機器。
- 直接複製知名作品、現成角色、商標或特定在世藝術家的精確風格。
- 背景中出現可讀的 AI 假文字、隨機標誌、浮水印、簽名、現代車輛、電線桿、塑膠製品等不合世界觀的物件。
- 只為「看起來很奇幻」而加入世界規則未定義的法陣、魔法生物、傳送門或全息人物。

### 1.3 畫面寫實程度

採用「可信材質＋概念插畫」而非照片級寫實。石材、金屬、鹽晶、木料和潮濕地面需要有可辨識質感；遠景細節可概括處理。小尺寸手機畫面下，輪廓、明暗分組和焦點比微小紋理更重要。

## 2. 色彩、光線、霧氣、材質與氛圍

### 2.1 全域基礎色票

以下為製作參考色，不是要求每張 AI 圖精準命中每一個 HEX。AI 背景可自然偏移，但整體色溫、飽和度和明暗層級必須接近。

| 色彩角色 | 參考色 | 用途 |
|---|---|---|
| 深石墨 | #252B2D | 深色石材、文字、最深陰影 |
| 風化石灰 | #A7A397 | 舊石、牆面、乾燥高光 |
| 霧灰 | #C5C8C3 | 遠景霧、柔和空氣透視 |
| 靜潮藍灰 | #657F88 | 海面、陰影、環境主色 |
| 深海藍綠 | #34575A | 海藻色材質、深處、舊金屬陰影 |
| 海藻綠 | #667B69 | 植被、工作服、自然元素 |
| 褪色赭土 | #A17C59 | 木料、舊皮革、少量暖色焦點 |
| 舊黃銅 | #9B8A61 | 磨損金屬、工程邊緣 |
| 界文微光 | #9BC6C0 | 極少量低亮度界文回應 |
| 危險提示 | #C58B67 | UI 警告或局部危險提示，節制使用 |

### 2.2 色彩比例

- 一般場景以約 70% 環境中性色、20% 區域主色、10% 以內焦點色作為視覺起點。
- 發光青綠只用於少數有明確界文／設備原因的區域，不可成為所有遺跡的常態。
- 暖色通常來自木料、鏽蝕、夕光、燈具或人的生活痕跡；不可無原因讓古代設備全身金光。
- UI 的文字和互動狀態需與背景有足夠對比；不要完全沿用背景低對比色。

### 2.3 光線規則

- 每張場景圖指定一個主要光源方向和一個主要環境光來源。
- 戶外預設柔和陰天光、低角度日光或散射天光；避免所有場景都用戲劇性夕陽。
- 室內遺跡以入口反射光、狹窄天光、低功率設備微光為主。
- 界文微光是設備工作狀態，不是裝飾燈帶；亮度和面積要克制。
- 重要調查物件必須在背景中可辨識，不可完全陷入黑影或被強逆光洗白。
- 角色臉部需有柔和可讀的正面或側前方補光，不可被特效遮蔽。

### 2.4 霧氣與空氣透視

- 靜潮海岸：貼近海平面的低霧、遠景低對比、灰藍空氣透視。
- 灰鐘台：風化石材、海霧掠過建築外緣，主建築輪廓保持清楚。
- 下層記錄室：少量浮塵與局部光束；不可用厚霧遮蔽讀取器和熱點。
- 霧層要柔和、透明、不規則；避免大片白色棉花狀雲霧。
- 動態霧氣使用 CSS 漸層或一張重用透明層即可，不要求每個場景生成獨立霧素材。

### 2.5 材質字典

| 材質 | 視覺特徵 | 應用 |
|---|---|---|
| 風化石灰岩 | 低對比、侵蝕邊緣、細微裂紋 | 灰鐘台、古代牆面 |
| 深灰玄武岩／硬石 | 重、暗、邊角磨損 | 基座、承重結構 |
| 舊黃銅與暗鐵 | 霧面、氧化、局部磨亮 | 扣件、刻度環、讀取器 |
| 潮濕木材 | 深色木紋、鹽霜、繩索磨痕 | 海岸測量設施、打撈物 |
| 鹽晶與沉積物 | 不規則結晶、白灰色薄層 | 靜潮海岸、鏡鹽相關素材 |
| 界文構件 | 幾何凹槽、重複刻痕、有限導光線 | 校準環、節點和記錄器 |
| 舊布與皮革 | 褪色、補縫、實用磨損 | 角色服裝與工具袋 |

材質應服務年代、環境和用途。不得把所有物件都做成同樣的金屬材質，也不可讓古代設備看起來像現代電子螢幕或玻璃觸控面板。

### 2.6 區域氣氛基準

| 區域 | 主色與光線 | 材質／氛圍 | 視覺區別 |
|---|---|---|---|
| 靜潮海岸 | 灰藍、霧灰、海藻綠；柔和散射天光 | 潮濕木料、鹽痕石材、風蝕金屬；安靜、警覺 | 海平線、低霧、歸航短線 |
| 霧杉內陸 | 深苔綠、冷灰、薄霧光 | 木材、根系、潮濕土石；遮蔽、幽深 | 垂直樹幹與層疊霧帶 |
| 鏡鹽盆地 | 象牙白、鹽灰、淡赭；硬而柔的反射光 | 鹽晶、乾裂地面、淺色石材；空曠、刺眼 | 大面積地平線與反射面 |
| 裂脊山地 | 石墨、鐵鏽赭、冷岩灰 | 斷層岩、工坊金屬、繩索與支架；堅硬、危險 | 斜向岩層與工程結構 |
| 玻璃內海 | 深藍綠、霧青、微弱銀光 | 玻璃狀沉積、潮水、半透明岩層；靜謐、難測 | 水平反射與深度層次 |

第一章只需把靜潮海岸的基準做穩；其他區域是未來擴充的風格錨點，不要求現在生成素材。

## 3. 場景構圖與視覺焦點

### 3.1 標準場景畫面

- 主背景預設以 16:9 橫向構圖設計，先確保桌面與橫向平板的完整場景。
- 主要可探索區域集中在畫面中央約 70% 範圍；重要焦點不可緊貼四邊。
- 每個場景最多一個主焦點與兩個次焦點。
- 以遠景、中景、前景的尺寸、對比、遮擋和霧度建立深度，不依賴大量分層。
- 背景圖不要放任何 UI、文字標籤、按鈕、箭頭或必須精準的可讀符號。
- 在畫面下方預留約 15–22% 的視覺安靜區，避免高細節與高對比干擾對話／任務 UI；實際 UI 高度由介面測試決定。
- 左右出口的方向由場景目錄和 UI 決定；背景可以提供視覺暗示，但不可只靠背景圖的箭頭表達出口。
- 不在背景中放置過小但被設定為必要線索的細節。

### 3.2 16:9 與直向手機

背景基準構圖為 16:9；直向手機不要求重新生成一張完全不同的背景。優先策略：

1. 使用同一張背景，以 cover 類方式顯示並確保主焦點落在安全區。
2. 重要焦點靠近中央，避免最左／最右邊緣有不可替代的關鍵內容。
3. 若直向裁切確實會切掉主焦點，先用 CSS 調整背景定位、縮放或容器高度。
4. 只有在 CSS 無法維持可讀性時，才生成一張同場景的直向備用構圖；它是獨立資產，不要求人工裁切。
5. 熱點座標由場景設定採用相對位置；直向版需調整熱點位置或顯示成列表，不能沿用錯位座標。

### 3.3 第一章三個場景的固定焦點

#### ch01_tide_mark — 潮痕灘

- 主焦點：中景偏右的舊潮位測量牌。
- 次焦點：遠景偏左的灰鐘台輪廓；前景或中景的居民歸航短線。
- 主要畫面：低潮灘、濕沙、打撈木料、灰藍海面、海霧。
- 氛圍：平凡工作中的微妙不安，不是災難現場。
- 重要差異：歸航短線是當代居民留下的安全標記；古代界文痕跡必須在材質、規律和年代感上可區分。
- 背景應可直接使用；禾汀可由單獨立繪或純文字對話呈現，不必烙進背景。

#### ch01_grey_bell — 灰鐘台

- 主焦點：觀測站的無指針鐘形構件。
- 次焦點：通往下層的入口；三道未封合圓弧的工程刻痕。
- 主要畫面：風化石材、舊金屬、海霧、局部低功率設備。
- 氛圍：曾經有明確用途的工程設施，現在沉寂但並非完全失效。
- 三道圓弧須以清楚、簡潔的形狀出現；如果 AI 無法準確生成，背景只呈現沒有可讀細節的刻痕區，正確符號由 CSS／SVG 疊加。
- 不要出現完整發光法陣、巨大全息人物或能自行說明歷史的裝置。

#### ch01_record_room — 下層記錄室

- 主焦點：中央低功率讀取器。
- 次焦點：封存架／殘缺記錄模組；維護痕跡與隔離標記所在的牆面。
- 主要畫面：狹窄石室、磨損金屬支架、局部設備指示光、少量浮塵。
- 氛圍：安靜、可操作、有風險但受控。
- 記錄器畫面不應包含可讀的 AI 生成文字；資料內容由遊戲 UI 顯示。
- 不呈現完整的古代人格或全息投影；「殘響」只是一段不完整的設備資料。

### 3.4 熱點和圖像的對齊

- 所有必要互動都要有可點擊區域和文字說明；不能要求玩家精準點擊一個幾像素的小物件。
- 熱點目標至少約 44×44 CSS px；小物件以透明擴大區域、圖示或文字標籤輔助。
- 熱點座標依 05_SCENE_CATALOG.md 與 06_JSON_SCHEMA.md 管理，不從圖片像素自動推測。
- AI 背景的物件位置有漂移時，優先調整熱點座標、標籤或選擇另一張背景，不要求人工移動圖內物件。
- 背景圖不是遊戲邏輯的唯一來源。即使圖片缺失，仍須能透過文字和備援畫面完成必要互動。

## 4. 角色、建築與道具的視覺語言

### 4.1 角色

角色設計以 04_CHARACTER_BIBLE.md 為準，本節只規範跨角色的通用視覺形式：

- 使用低飽和敘事插畫；材質、輪廓與職業線索比華麗裝飾重要。
- 第一章可視的當代角色立繪上限為一位，優先使用禾汀一張基礎肖像。
- 肖像以胸像或半身、正面或四分之三側面為主，臉部清楚，頭頂與肩部留安全邊界。
- 背景透明是加分項，不是必要條件。若工具無法輸出透明圖，使用純色或簡潔背景，直接作為矩形肖像卡，不做手動去背。
- 不把姓名、對話、表情符號、UI 或水印畫進圖中。
- 第一章不要求表情差分、走路圖、戰鬥姿勢、嘴型同步或逐格動畫。
- 若角色一致性難以維持，使用一張基礎肖像；情緒以對話文字、標點、邊框或 UI 狀態表達。

#### 禾汀的外觀鎖定

以下以 04_CHARACTER_BIBLE.md 為準，不可由美術提示詞任意改寫：

- 成年靜潮海岸居民，深棕至黑色的簡單束髮／短髮輪廓。
- 灰藍、海藻綠、褪色赭色的耐磨工作服。
- 實用腰帶、防滑靴、小型岸標工具或短繩扣。
- 自然日曬感，務實、警覺、可靠；不是貴族、戰士或魔法師。
- 柔和自然光、低飽和材質感，無超自然發光。

### 4.2 建築與遺跡

- 建築形體須看得出功能：觀測、校準、記錄、維護、通行或承重。
- 古代科技以材料、凹槽、環形構件、刻度、接合面和維修痕跡表現；不可全靠發光線。
- 風化要有方向與原因：迎風面磨損、接縫沉積、低處潮痕、金屬氧化。
- 同一座建築的主要輪廓、入口位置、環形構件與大尺度比例在同場景素材中保持一致。
- 需要精確一致的標誌、三道未封合圓弧、無指針鐘面等，若 AI 生成不可靠，使用程式疊加的 SVG／CSS 圖形或文字說明。
- 不為第一章生成建築的多角度模型；一張背景即可滿足探索流程。

### 4.3 道具與可調查物件

- 道具以單一主體、清楚輪廓、簡潔背景為主。
- 物件圖適合以方形或 4:3 比例呈現；道具辨識度比背景細節重要。
- 若工具支援透明背景，可直接使用；否則以純色背景的道具卡、方形裁切或 CSS 框呈現，不做人工去背。
- 必要符號和可讀文字由 HTML/CSS/SVG 顯示，避免直接讓生成模型畫出精準文字。
- 道具圖應與場景背景有明暗區別，但不必模仿真實遊戲內的動態光照。
- 第一章的測量牌、無指針鐘、讀取器、封存模組可直接使用背景中的物件加上熱點，不需要為每一個熱點另外生成一張圖。

### 4.4 界文與象徵圖案

- 界文是受材料、能源、校準和資料限制的工程系統，不是隨意發光的魔法文字。
- 主要視覺形式：刻痕、幾何凹槽、重複分段、環形校準結構和有限的低亮度導光。
- 三道未封合圓弧的缺口方向、線寬與相對比例必須固定；如需精準呈現，建立一份簡單 SVG 母版並重用，不依賴每次 AI 重畫。
- 無指針鐘是同步偏差的視覺象徵，不代表預知未來。
- 歸航短線是當代居民的生活標記，不應被畫成古代高科技裝置。
- 未確認用途的符號不得直接標註為宗教、王權或世界核心符號。

## 5. 背景與 UI 的視覺區分

### 5.1 背景負責什麼

背景只負責環境、深度、材質、光線和情緒。背景不得承擔必須精確顯示的文字、任務狀態、互動選項或解鎖條件。

### 5.2 UI 負責什麼

UI 由 HTML/CSS 和資料驅動，統一負責：

- 場景標題、環境描述、對話和角色名字。
- 熱點標籤、出口、鎖定原因和調查狀態。
- 任務進度、線索簿、物件檢視、選擇按鈕和章末摘要。
- 三道圓弧、歸航短線等需要精準重複的簡單符號。
- 資產載入失敗時的背景漸層和提示。

### 5.3 UI 視覺語言

- 以深石墨半透明底、風化石灰文字、低飽和青綠作為互動強調色。
- 面板應有足夠對比和清楚層級，不要直接仿造難以閱讀的裝飾字體。
- 主要正文優先使用系統可讀字體；標題可使用同一字體的較大字重，避免依賴外部付費字型。
- 熱點狀態至少區分「未調查」「已調查」「目前不可用」；不可用狀態必須提供原因。
- 所有重要資訊必須能以文字讀取；顏色不能是唯一的狀態提示。
- UI 裝飾不可遮住必要熱點、場景焦點或手機安全區。
- 圖片中不要包含按鈕或文字，以免不同語言、不同螢幕比例時無法調整。

### 5.4 圖示策略

優先順序：

1. HTML 文字標籤與 CSS 幾何圖形。
2. 可重用的簡單 SVG 圖示。
3. 一組風格統一的 AI 生成圖示（只在前兩種不足時使用）。

不要為每個按鈕生成獨立圖片。熱點、出口、線索新提示、鎖定狀態應共用同一套圖示和狀態規則。

## 6. 圖片比例、解析度、格式與效能

### 6.1 建議規格

| 資產類型 | 建議比例 | 建議像素尺寸 | 首選格式 | 備註 |
|---|---|---|---|---|
| 場景主背景 | 16:9 | 1536×864；可用 1920×1080 | WebP | 低於此尺寸可先測試；避免不必要的超大圖 |
| 直向備用背景 | 9:16 | 900×1600 或 1080×1920 | WebP | 僅在 CSS 無法保護焦點時生成 |
| 透明前景／中景 | 16:9 畫布或符合場景的寬幅 | 1536×864 起 | PNG／WebP（確認透明支援） | 可選；透明通道失效時不可當作正式透明層 |
| 角色肖像 | 3:4 或 4:5 | 768×1024 或 832×1040 | WebP；需透明時 PNG | 單張基礎肖像即可 |
| 道具卡圖 | 1:1 或 4:3 | 768×768 或 1024×768 | WebP／PNG | 優先單一主體、簡潔背景 |
| UI 小圖示 | 1:1 | 64–256 px | SVG／PNG | CSS/SVG 優先 |
| 霧氣／微光覆層 | 16:9 或寬幅 | 1024×576 至 1536×864 | PNG／WebP | 只有確認透明度正確時才使用 |
| 紋理／粒子貼圖 | 1:1 或寬幅 | 256–1024 px | PNG／WebP | 優先由 CSS 粒子取代 |

這些是目標而非硬性生成門檻。若免費工具只允許較低解析度，先使用可用尺寸測試；不因追求尺寸而付費或停工。

### 6.2 檔案大小目標

- 背景圖目標盡量低於約 500 KB；超過時先評估轉為 WebP、降低解析度或改用另一張較簡潔圖片。
- 角色肖像和道具圖盡量低於約 250 KB。
- 共用透明效果圖盡量低於約 200 KB。
- 這些是壓縮目標，不是絕對門檻；畫面品質明顯受損時，保留較大檔案並記錄原因。
- 第一章三張主背景優先最佳化。不要在同一畫面同時載入多張大型透明圖層。
- 不把圖片轉成 Base64 或巨大文字塞進 JSON；資產以相對檔案路徑引用。

### 6.3 轉檔與壓縮的無修圖原則

如果生成工具能直接輸出 WebP，優先使用；否則可先用原始 PNG/JPEG 測試。只有在檔案過大或格式不相容時，才使用可在手機瀏覽器操作的免費轉檔工具。轉檔只屬於格式／壓縮，不應要求修補、去背或手動切圖。每次轉檔後需確認畫面沒有明顯色偏、透明通道丟失或嚴重壓縮瑕疵。

### 6.4 圖片路徑

依 06_JSON_SCHEMA.md 的正式建議目錄：

~~~text
assets/
  art/
    backgrounds/
    characters/
    props/
    ui/
    effects/
~~~

完整相對路徑唯一以 `data/assets.json` 登錄的 `path` 為準。本文列出的檔名是檔名簡稱，不可當作完整路徑或遊戲資料中的資產 ID。GitHub Pages 專案使用相對於專案根目錄的路徑，不使用本機絕對路徑、外部臨時下載網址或 `..` 路徑。

## 8. AI 生成工作流程與角色一致性

### 8.1 每次生成前的固定流程

1. 確認需求來自哪份正式文件、scene ID／character ID 是什麼。
2. 先寫清楚用途、比例、主焦點、主色、光源和禁止元素。
3. 使用本文件的固定提示詞模板，再填入場景／角色專屬描述。
4. 若工具支援參考圖，使用已驗收的風格基準圖或角色基礎肖像。
5. 若工具不支援參考圖、固定種子、遮罩或分層，不把這些能力當成前提。
6. 一次生成少量候選圖；先檢查構圖和一致性，再決定是否重試。
7. 不為了微小瑕疵無限重生；若不影響遊戲，優先以 UI、裁切定位或替代素材處理。
8. 記錄工具、生成日期、提示詞版本、輸出尺寸、來源和授權檢查狀態。
9. 驗收通過後才放入正式資產目錄並更新 assets.json。

### 8.2 角色跨圖片一致性

依以下優先順序控制一致性：

1. **一張圖策略（第一章預設）**：每個角色只生成一張正式基礎肖像，所有情緒由文字、對話框或 CSS 呈現。
2. **參考圖策略**：若工具支援圖片參考，始終引用同一張已驗收的角色基礎圖，並在提示詞重複外觀鎖定。
3. **固定描述策略**：保存同一份角色描述，逐字重用，不在每次生成時改寫髮型、年齡、服裝、配件和光源。
4. **相同構圖策略**：保持相同鏡頭距離、胸像範圍、角度、背景簡潔度和比例。
5. **差分限制策略**：只有在基礎肖像一致性足夠時，才考慮生成表情差分；若差異明顯，退回一張圖策略。

不得假設同一提示詞或同一種子一定能生成完全相同的人物。第一章不要求嘴型動畫、連續姿勢或全身多角度素材。

### 8.3 角色外觀鎖定卡

每個需要重複出現的角色，在提示詞前保存一段固定鎖定卡：

- 角色 ID 與正式姓名。
- 成年／年齡感、臉型輪廓、髮色與髮型。
- 固定服裝的主色、剪裁、材質。
- 不可缺少的配件。
- 固定鏡頭距離、角度、光線與畫風。
- 明確列出不得變動的項目。
- 允許變動的項目只限表情、輕微頭部角度和場景明暗。

第一章的禾汀鎖定卡以 04_CHARACTER_BIBLE.md 的第 9 節為準，不得另創矛盾版本。

### 8.4 場景一致性

- 先為每個區域建立一張「風格錨點圖」；第一章以潮痕灘主背景作為靜潮海岸的首要錨點。
- 同一地點的後續圖片沿用相同色溫、霧度、材料、天氣和建築輪廓描述。
- 相鄰場景可以改變明暗和空間密度，但不應突然轉成高飽和、不同渲染方式或不同科技年代。
- 對同一座灰鐘台，無指針鐘、環形構件、下層入口和主要石材應保持可辨識的形態關係。
- 若生成圖彼此不一致，優先選擇最符合場景目錄的一張作為正式版本；不要求用修圖拼接不同版本。
- 同一張背景可重用於不同互動狀態；透過 CSS 微光、文字描述和熱點狀態營造變化。

### 8.5 提示詞中的禁止元素

依場景需要加入以下負面限制；如果工具沒有獨立負面提示詞欄位，將它們放在主提示詞末尾：

- 不要文字、字母、數字、浮水印、簽名、品牌標誌。
- 不要現代電子設備、塑膠物件、現代交通工具或不合世界觀的服飾。
- 不要過度飽和、霓虹燈、鏡面塑膠、滿屏魔法粒子。
- 不要多餘人物、重複肢體、變形手部或無關武器。
- 不要遮住主要焦點、不要把必要物件放在畫面最邊緣。
- 不要把 UI、按鈕、字幕、對話框畫進圖片。
- 不要精確模仿受著作權保護的特定角色、作品或特定在世藝術家的風格。

## 10. 不需人工修圖的替代方案

### 10.1 AI 無法精準分層時

**正式預設：完整背景圖優先，分層不是前置條件。**

採用下列降級順序：

1. 直接使用一張構圖完整的主背景。
2. 使用 CSS 背景定位、緩慢縮放或微小平移營造深度感。
3. 用 CSS 漸層製作霧氣、光暈和暗角。
4. 用 CSS／Canvas 生成少量微塵、海霧粒子或微光粒子。
5. 只有在工具能直接輸出真正透明圖層時，才加入可選前景／中景。
6. 若分層邊緣、透視或透明度不自然，移除圖層，不嘗試手工拼接。

任何場景都必須在「只有一張背景圖＋UI」的狀態下仍然可用。

### 10.2 透明背景失敗時

- 角色：使用純色或簡潔背景，放在有邊框的矩形肖像卡內。
- 道具：保留純色背景作為物件檢視卡，不做去背。
- 霧層：不生成圖片，改用 CSS 漸層和透明度動畫。
- 微光：用 CSS radial-gradient 或簡單的發光邊框。
- 前景：移除該層，改用完整背景的構圖與視差。

不得以要求擁有者手動擦除背景作為唯一解法。

### 10.3 生成符號與文字失準時

- 不要求 AI 畫準確的界文符號、三道圓弧、刻度、銘牌文字或介面讀數。
- 背景保留抽象刻痕或空白牌面。
- 精準圖案以 CSS、簡單 SVG、HTML 文字或既有 UI 元件疊加。
- 若連 SVG 編輯也不方便，使用文字描述和互動面板呈現線索，不要求一定要把符號畫出來。

### 10.4 角色跨圖不一致時

- 停止生成更多表情差分。
- 回到單張基礎肖像。
- 使用同一張圖搭配不同對話文字和簡單淡入淡出。
- 若角色圖品質仍不穩定，改用姓名、對話框和場景物件，不阻擋主線。

### 10.5 AI 圖片構圖與場景目錄不符時

- 優先重生一張完整背景，提示詞明確描述主焦點和構圖。
- 若只是焦點稍微偏移，可調整 CSS 背景定位和熱點座標。
- 若關鍵建築、入口或互動物件缺失，不能把它當作正式背景；改用符合要求的候選圖。
- 不要求人工把多張圖拼接成一張。

### 10.6 免費額度或工具不可用時

依序降級：

1. 先用 CSS 漸層背景和場景描述完成流程。
2. 重用已驗收、授權狀態清楚的同區域背景。
3. 使用簡單幾何形狀、文字卡和 UI 圖示。
4. 減少非必要特效與角色圖片。
5. 延後非第一章內容。

不可因為免費額度用完就轉向未確認授權的圖片、付費服務或付費 API。

## 11. 素材授權與免費使用檢查流程

### 11.1 基本原則

- 「AI 生成」不等於必然沒有著作權、商標、肖像或服務條款風險。
- 免費使用不必然等於可商業使用，也不代表可以重新散布或不署名。
- 不把任何素材標示為「可商用」除非已核對適用條款。
- 不能確認來源或授權的素材先隔離，不進正式發布包。
- 本文件不是法律意見；若服務條款不清楚，選擇更明確且風險較低的來源。

### 11.2 AI 生成素材檢查

每次使用圖像工具前／後，確認：

1. 工具與服務名稱、生成日期和當時適用的服務條款可查。
2. 免費方案是否允許保存、公開展示和用於 GitHub Pages。
3. 是否要求署名、標示 AI 生成、附帶連結或保留特定聲明。
4. 是否對商業使用、公開專案、輸出尺寸、再散布或敏感題材設有限制。
5. 是否允許把生成結果放進公開的 GitHub repository。
6. 圖像中是否意外包含商標、現成角色、可辨識的真實人物或疑似受保護作品元素。
7. 記錄檢查日期和條款連結；條款不明就標記「待確認」，不可當作已核准。

### 11.3 外部圖片素材檢查

對每張非自行生成圖片記錄：

- 素材 ID、檔名、用途與下載日期。
- 原始來源頁面 URL 和作者／發布者（若可得）。
- 授權名稱、授權版本和條款連結。
- 是否允許公開展示、修改、再散布和商業使用。
- 是否要求署名、附上授權文本或標記修改。
- 是否含有第三方商標、人物肖像或額外限制。
- 核查狀態、核查日期與簡短備註。

不可只憑搜尋結果縮圖、社群貼文或「免費下載」按鈕判斷授權。

### 11.4 授權狀態標準

## 12. 素材管理與 assets.json 整合

### 12.1 每個正式素材的最低欄位

每項圖片需有穩定 asset ID、檔案路徑、格式、替代文字、用途、必要性和備援設定；資料結構遵循 06_JSON_SCHEMA.md，不得自行發明衝突欄位。

建議清單欄位（用於管理紀錄，不表示全部都要放入 assets.json）：

| 欄位 | 用途 |
|---|---|
| Asset ID | 唯一識別碼 |
| File name / path | 正式檔名與相對路徑 |
| Type | 背景、角色、道具、UI 或效果 |
| Related ID | scene ID、character ID 或 prop ID |
| Required | 是否為第一章流程必要 |
| Dimensions / format / size | 技術規格 |
| Prompt / source | 生成提示詞或原始來源 |
| License status | 授權檢查狀態 |
| Review status | 草稿、待驗收、通過、淘汰 |
| Fallback | 缺檔時的備援方式 |

### 12.2 正式素材狀態

- draft：剛生成或取得，尚未驗收。
- review：正在檢查構圖、風格、授權或檔案品質。
- approved：可投入正式遊戲。
- rejected：不使用，避免被誤認為正式資產。

狀態可以記錄在 Markdown 資產表或工作紀錄中；不要把 06_JSON_SCHEMA.md 未定義的欄位擅自加入 assets.json。

### 12.3 缺圖備援

- 背景圖失敗：顯示該區域色系的 CSS 漸層、場景標題與描述。
- 角色肖像失敗：隱藏肖像，只保留姓名與對話。
- 道具圖失敗：使用文字物件檢視卡。
- 霧氣／微光圖失敗：直接停用特效。
- UI 圖示失敗：改用文字、CSS 幾何圖形或符號字元。
- 任一可選圖層失敗不得阻止玩家調查、取得線索或切換場景。

- [ ] 直向和橫向顯示時，焦點、出口和 UI 不互相遮擋。
- [ ] 視差、霧氣和粒子可以關閉或降級。
- [ ] 第一章在只使用三張主背景的情況下仍能完成。

### 14.5 授權與來源

- [ ] 來源 URL 或生成工具已記錄。
- [ ] 使用條款與免費方案限制已檢查。

- [ ] 不明來源素材未放入正式發布包。
- [ ] 沒有明顯的商標、受保護角色或真實人物肖像風險。

### 14.6 第一章發布門檻

- [ ] 三張必要背景全部通過驗收。
- [ ] 三張背景各自都能在沒有透明圖層時使用。

## 15. 給後續 AI 協作者的工作規則

任何 AI 生成或整理美術素材時，必須遵守：

1. 先閱讀 00_PROJECT_MASTER.md 與 01_WORLD_BIBLE.md，確認產品限制和世界規則。
2. 依 02_STORY_BIBLE.md 檢查這張圖能否透露該章節尚未揭露的真相。
3. 依 03_GAMEPLAY_SPEC.md 保持手機觸控、對比和效能要求。
4. 依 04_CHARACTER_BIBLE.md 鎖定角色外觀；不自行改名、改衣著或改身份。
5. 依 05_SCENE_CATALOG.md 保持場景 ID、焦點、熱點、出口與素材用途一致。
6. 依 06_JSON_SCHEMA.md 登錄穩定資產 ID、相對路徑、格式和備援。
7. 優先輸出一張可直接使用的完整背景，不把分層當成生成成功的必要條件。
8. 不要求擁有者手動修圖、去背、逐張切圖或使用付費軟體。
9. 不可把未核對授權的素材標記為已批准。
10. 交付時清楚說明哪些素材已生成、哪些只是提示詞、哪些已驗收、哪些仍待授權檢查。
