## 0. 使用規則與決策標記

本文件是角色內容的單一來源。劇情、JSON、程式、美術提示詞及測試文件應引用角色 ID，不應自行發明同一角色的別名或外觀。

- **[定案]**：跨章節必須一致，除非正式修訂本文件。
- **[第一章可知]**：第一章玩家可以從對話或證據合理得知。
- **[隱藏真相]**：作者層級資料，角色不一定知道，第一章不得直接說出。
- **[製作建議]**：為低成本實作而採用的預設方案。
- **[待後續定義]**：可以擴充，但目前不可寫成既成事實。

### 0.1 核心原則

1. 角色不是百科全書。每人只知道符合其生活經驗、職務、接觸來源與年代的資訊。
2. 角色可以誤判，但文本要能指出那是角色觀點，而非作者保證的客觀事實。
3. 不把任何人設定成唯一能解開世界謎團的「天選者」。推理依賴證據、比對與選擇。
4. 第一章只正式呈現一名當代主要 NPC「禾汀」、玩家角色，以及無人格的設備殘響。瑟嵐可透過訊息或聯絡標記作遠端伏筆，不需製作完整立繪。
5. 一張基礎立繪搭配最多三個表情變體即可。姿勢變化優先使用文字、肖像裁切、對話框和場景切換，不要求逐格動畫。
6. 角色外觀不可用來暗示其善惡。服裝、工具和姿態首先反映職業、環境與資源條件。
7. 角色 ID 一旦被 JSON 或存檔引用，不得因改名而變更；顯示名稱可以在正式修訂時調整。

## 1. 角色 ID 與資料格式規則

角色 ID 使用小寫蛇形命名，採用 `char_` 前綴；劇情事件、對話和場景都引用此 ID。

建議資料欄位：

- `id`：穩定角色 ID。
- `display_name`：玩家看到的名稱。
- `role`：敘事職能。
- `first_appearance`：首次出場場景或事件。
- `visual_key`：角色視覺基準 ID。
- `knowledge_stage`：角色可知資訊階段。
- `asset_prefix`：素材檔名固定前綴。

正式 JSON 欄位名稱由 `06_JSON_SCHEMA.md` 統一；本文件的欄位名稱是語意建議，若技術文件另有定案，需同步更新而不可雙軌並存。

## 3. 玩家角色：`char_player`

### 3.1 身分與動機

- **[定案] 公開身分**：受託進行沿岸測量與遺跡初步安全檢查的外勤調查者。玩家不是軍隊指揮官、王室繼承人、預言中的人物或天生具有特殊能力的人。
- **[定案] 工作能力**：觀察現場、使用基礎測量工具、閱讀常見警示標記、整理物證與提出有限度推論。
- **[製作建議] 個人背景**：不在第一章鎖定性別、年齡、族裔、家庭或完整身世。用「你」或「調查者」敘述，避免製作多套立繪和分支。
- **探索動機**：最初是完成工作、確認測量標記是否可靠並避免居民誤入危險區。當灰鐘台記錄出現日期矛盾後，動機擴展為查清來源、理解哪些證據被保存或遺失，以及如何避免未經驗證的歷史再次影響當代人。
- **內在矛盾**：想讓證據被看見，但也知道過早公開可能使遺跡遭搶拆、讓不完整資訊被當成定論。
- **角色弧線**：由「記錄現象的人」成長為「願意對證據解釋和資訊流向負責的人」，而不是獲得超能力或成為全知者。

### 3.2 資訊邊界

**第一章可以知道：**
- 沿岸近期存在異常讀數與低頻回應。
- 灰鐘台具有觀測設施的用途特徵。
- 殘響是不完整的設備資料。
- 某筆日期與現行年表不一致，值得獨立驗證。

**第一章不知道：**
- 第一次界潮的完整因果。
- 空白年各地記錄斷裂的全部原因。
- 定本計畫的全貌及所有責任歸屬。
- 重新響應節點的確切啟動者或唯一原因。
- 世界起源、界隙的最終本質，以及任何尚未由證據支持的答案。

### 3.3 對話與呈現

- 玩家選項應短、清楚、可預期，例如「封存原始碎片」「分享標註摘要」「先核對外部刻痕」。
- 不強迫玩家說出角色沒有證據支持的專業結論。
- 不需玩家立繪。對話時顯示角色名稱與選項即可；需要視覺回饋時用物件特寫或線索卡。
- 玩家角色的心理以少量內心文字呈現，不以長篇第一人稱獨白解說世界史。

### 3.4 玩家角色素材

- 必要：無。
- 可選：`art/props/player_field_notes.webp`（手帳／測量筆記特寫）。
- 不製作玩家臉部、全身立繪、走路動畫或多套服裝，除非日後正式決定玩家外觀為固定角色。

## 4. 第一章主要角色

## 4.1 禾汀：`char_hetin`

### 身分、目標與矛盾

- **公開身分**：靜潮海岸居民，熟悉當地潮況、航路、安全記號與沿岸生活。
- **眼前目標**：讓外勤調查者確認測量標記的異常，同時避免灰鐘台被當成可任意拆解的廢物。
- **長期目標**：保護居民的生活區與航路，讓外來研究者先理解地方風險，再進入遺跡。
- **矛盾**：她／他需要外部專業協助，卻不信任只帶走資料、不承擔現場後果的調查隊。
- **背景**：成長於靜潮海岸，透過日常工作累積潮汐與岸標知識。不是古代史專家，也沒有特殊感知能力。
- **[第一章可知]** 最近數週灰鐘台附近偶有低頻共鳴；居民因此避開部分路段，並加強歸航短線標記。
- **[隱藏真相／角色未知]** 禾汀沒有掌握節點重新響應的真正原因，也不應被寫成暗中監控玩家的神秘守門人。
- **信任建立方式**：玩家有沒有仔細測量、是否尊重隔離標記、是否說明資料的不完整性。
- **第一章變化**：玩家封存原始碎片時，禾汀認為其謹慎；玩家分享標註摘要時，禾汀較願意提供地方脈絡，但仍要求不要誇大結論。

### 固定外觀特徵

- 成年沿岸居民；性別呈現可在製作時固定為單一版本，建議使用中性、自然的輪廓，避免依性別套用刻板服飾。
- 中等身形，姿態穩健，皮膚呈長期戶外生活的自然日曬感。
- 深棕或黑色頭髮，簡單束起或短髮；髮型輪廓清楚，方便各表情圖維持一致。
- 穿耐磨的海岸工作外套、內層布衣、實用腰帶與防滑靴；色彩以灰藍、海藻綠、褪色赭色為主。
- 配戴一件固定的小型岸標工具或短繩扣，作為輪廓辨識點；不可每張圖改成不同飾品。
- 不使用發光眼睛、魔法符文、貴族徽章或誇張武器。

### 可改變項目

- 表情：中性、擔心、放鬆／認同。
- 姿勢：標準站姿、手指向岸標、低頭看測量牌。優先使用裁切或文字描述，不要求三套全身姿勢。
- 可變光線：只允許場景光照不同，不可改變服裝基本色或角色年齡。

### 對話風格

- 直接、務實、關心現場後果。
- 先說潮況、路線、工具、工作，再談抽象問題。
- 句子短，少用學術術語；不會把古代傳說當成確定史實。
- 常用表達示例（可改寫，不是固定台詞）：
  - 「那道線不是裝飾，是提醒人別走錯潮路。」
  - 「你可以記下它，但別急著說你已經懂了。」
  - 「這裡的人要的不是一個漂亮答案，是明天還能安全出海。」
- 避免：長篇哲學演說、無理由的敵意、突然揭露世界真相、把玩家稱作命定之人。

### 第一章出場位置

1. `ch01_tide_mark`：首次短對話，說明測量委託和最近異常。
2. `ch01_tide_mark`：玩家完成必要測量後，提醒灰鐘台的隔離與安全原則。
3. `ch01_record_room` 之後：以簡短對話或回報畫面承接玩家的資料處理選擇；不需要同一場景內即時演出。
4. 章末：確認玩家已記錄線索，指向後續比對方式，不提供答案。

### 禾汀素材需求

- 必要：一張半身或胸像立繪、透明背景。
- 建議表情：`neutral`、`concerned`、`reassured`。
- 可選：一張指向岸標的簡單姿勢；如果生成一致性不佳，直接不做。
- 檔名：
  - `art/characters/char_hetin_base.webp`
  - `art/characters/char_hetin_neutral.webp`
  - `art/characters/char_hetin_concerned.webp`
  - `art/characters/char_hetin_reassured.webp`
- 若表情變體難以生成一致，先只用 `char_hetin_base.webp)，用對話文字與標點承擔情緒差異。

## 4.2 灰鐘台維護殘響：`char_greybell_echo`

### 身分與功能

- **公開名稱**：灰鐘台維護殘響。
- **本質**：設備保存的低完整度感測、操作或狀態資料片段，不是靈魂、人工智慧人格、完整影像回放或能自由回答問題的 NPC。
- **目標**：沒有可證實的個人目標；只會依保存資料和當前設備條件呈現有限反應。
- **敘事功能**：提供操作順序、缺漏欄位、警示符號或短促聲光反應，協助玩家理解設備狀態。
- **[第一章可知]** 讀取資料有中斷、缺欄和時間標記異常。
- **[隱藏真相]** 殘響的來源和完整保存條件須透過後續工程證據確認。不可在第一章斷言是哪位古代人物留下，也不可把它寫成全知旁白。
- **限制**：不能辨識玩家身分、不能自由交談、不能解釋第一次界潮、不能預測未來、不能提供沒有被設備記錄的事件。

### 視覺識別

- 不設人臉、人體、幽靈輪廓或透明人影。
- 只用固定的界文構件、低亮度指示點、斷裂的短線圖樣、資料文字和不完整讀取框。
- 色彩以暗石灰、低飽和青藍與少量暖白指示光為主。
- 所有視覺效果可用靜態圖加 CSS 淡入／亮度變化；不需要粒子系統或 3D 特效。

### 對話／訊息表現

- 內容使用短句、欄位、錯誤碼或被截斷的操作提示。
- 例：`校準……未完成。`、`記錄區段：缺失。`、`日期欄：無法與本地表對齊。`
- 不使用帶人格的語氣、幽默、恐懼、稱呼玩家或完整句式長篇敘述。
- 若呈現聲音，只能是可選的短促機械音；第一章無音效仍須可理解。

### 素材需求

- 必要：一張設備局部或界文讀取面板插圖，可由場景背景重用。
- 建議檔名：
  - `art/characters/char_greybell_echo_panel.webp`
  - `art/ui/echo_fragment_frame.webp`
- 不需要角色立繪、表情差分、配音或動畫序列。

## 5. 重要配角與勢力代表（後續章節預設）

以下人物提供後續章節的人際視角，讓不同勢力的立場透過具體工作與代價呈現，而非由單一反派代表所有問題。第一章不需要生成這些人物圖片。

## 5.1 瑟嵐：`char_seran`

- **身分**：校勘院聯絡人，負責接收地方調查者的初步材料並提供檔案比對方法。
- **目標**：保留來源、日期、讀取條件與不確定性，避免殘缺記錄被直接寫入正式年表。
- **矛盾**：希望更多人能檢視證據，但公開未校準資料可能讓錯誤解讀迅速擴散。
- **秘密／限制**：第一章沒有足夠證據證明瑟嵐知道節點重新響應原因；不能把她／他寫成早已掌握全部真相。任何涉及其過去接觸高風險檔案的設定，須待後續章節正式定案。
- **關係**：對玩家保持專業合作；對禾汀尊重地方知識，但會要求把口述資訊與物證分欄記錄；對定本監理局既有制度合作，也對其封存權限保持審慎。
- **對話風格**：精確、謹慎、常問「來源是什麼」「能否獨立比對」「哪些部分只是推測」。
- **第一章出場**：章末以短訊息、聯絡標記或線索簿中的聯絡管道出現；不要求臉部立繪。
- **視覺識別**：文件印記、校勘標記、簡潔的文字訊息介面；後續正式登場再定衣著。
- **素材**：`art/ui/char_seran_message_icon.webp`（可選）；後續若正式出場再使用 `art/characters/char_seran_base.webp`。

## 5.2 瑪嶺：`char_maerin`（海岸公約會代表）

- **身分**：海岸公約會的地方協調者，負責遺跡周邊居民、安全路線與調查許可的協調。
- **目標**：避免研究活動破壞沿岸生活與公共安全。
- **矛盾**：封鎖可以降低風險，也可能讓外界無法檢驗地方說法。
- **秘密／資訊邊界**：掌握的是當代沿岸事故和居民決議，不掌握古代界潮完整成因。
- **關係**：與禾汀共享地方安全關切，但在是否允許外來研究者進入方面可能有不同看法；對校勘院要求公開來源，對定本監理局的高風險管制則要求地方監督。
- **語氣**：行政而實際，關注誰負責、何時撤離、如何補償。
- **首次出場建議**：第二章，於聚落會議或遺跡通行協商場景。
- **視覺／素材**：耐用的地方公約工作服、簡潔的岸線徽記；`art/characters/char_maerin_base.webp`，正式製作時再定表情需求。

## 5.3 伊爾文：`char_ilven`（校勘院研究者）

- **身分**：校勘院檔案研究者，專長於不同地區的日期格式、來源標記與抄錄版本。
- **目標**：建立可重複驗證的證據鏈。
- **矛盾**：嚴格標準能降低錯誤，也可能使沒有標準格式的地方證詞被低估。
- **秘密／資訊邊界**：知道學界對空白年的解釋有分歧，不知道唯一答案。
- **關係**：與瑟嵐可設為同事，也可在控制角色數量時合併為同一角色；與禾汀需要學習如何記錄口述脈絡。

### 6.2 關係寫作規則

- 不預設角色間的浪漫關係，也不以戀愛支線增加第一章工作量。
- 角色間衝突要有明確利益或方法差異，不用無端侮辱、誤會拖戲。
- 同一角色可對不同選擇有不同反應，但其核心價值觀不能在沒有事件原因時任意反轉。
- 不使用單一「好感度」概括所有信任。至少區分「資料可信度」「地方合作意願」「安全風險接受度」等敘事概念；是否做成程式變數由玩法與技術文件決定。
- 玩家可以不同意角色，但不可因一次選項使角色立即知道玩家沒有公開的資訊。

- 不要求配音。文字本身必須能傳達說話者差異。

## 9. 視覺識別與 AI 角色圖片規格

### 9.1 全專案共通美術規則

- 風格：低飽和、具材質感的敘事探索遊戲插畫；偏寫實手繪／概念設計，不走高反光 3D、偶像立繪或過度華麗的動漫裝飾。
- 光線：柔和、可讀；角色臉部不可被過強逆光或發光特效遮蔽。
- 背景：生成角色立繪時使用透明背景；若工具無法輸出透明背景，改用純色或簡單背景，後續直接裁切或改採場景內角色肖像，不要求手動去背。
- 構圖：半身或胸像、正面或四分之三側面、角色置中、肩部和頭頂留有安全邊界；適合手機畫面對話框旁的小尺寸呈現。
- 色彩：服裝以少量固定主色為主；避免細碎花紋、透明薄紗、複雜飾品、文字標誌和大量裝甲。
- 角色比例：同一角色所有表情圖保持相同年齡感、臉型、髮型、衣服、配件、鏡頭距離與光源方向。
- 圖片不得內嵌姓名、對話、UI、浮水印、簽名或隨機文字。遊戲文字一律由 HTML/CSS 顯示。
- 不要求角色每次生成都完全相同的細小紋理；優先保住輪廓、髮型、主色、固定配件和服裝形狀。
- 如果無法穩定生成多張一致圖片，採用「一張基礎圖＋CSS 淡入淡出＋文字表情」方案，不進行手動修圖。

### 9.2 禾汀固定外觀鎖定清單

**必須一致：**
1. 深色、簡單、易辨識的髮型輪廓。
2. 灰藍／海藻綠／褪色赭色的沿岸工作服配色。
3. 耐磨外套、腰帶與防滑靴的實用風格。
4. 固定的小型岸標工具或短繩扣。
5. 成年、長期戶外工作者的自然氣質。
6. 低飽和、柔和自然光，無超自然發光。

**可以改變：**
- 眉眼、嘴角等少量表情。
- 頭部輕微角度。
- 手勢（只有另有獨立姿勢素材時）。
- 場景造成的柔和明暗差異。

**不可以改變：**
- 年齡感、臉型、髮色、髮型主輪廓。
- 外套主色、衣領、固定配件。
- 角色的族裔特徵或性別呈現（若正式美術定稿後已固定）。
- 突然加入魔法光效、武器、貴族徽章或新制服。

### 9.3 AI 生成提示詞模板

每次生成前先複製同一份「固定外觀描述」，只替換表情或姿勢描述。不要每次重新自由發明角色。

**禾汀基礎立繪提示詞：**

> 為敘事探索遊戲《零界紀元：THE UNWRITTEN WORLD》繪製同一位固定角色禾汀的半身角色立繪。成年靜潮海岸居民，深棕至黑色的簡單束髮／短髮輪廓，長期戶外工作形成自然日曬感，穿灰藍、海藻綠與褪色赭色為主的耐磨海岸工作外套、實用腰帶，固定配戴小型岸標工具或短繩扣。氣質務實、警覺、可靠，不是貴族或戰士。低飽和、具材質感的手繪概念插畫，柔和自然光，正面略帶四分之三角度，胸像構圖，臉部清晰，輪廓簡潔，適合手機遊戲對話框旁的小尺寸顯示。背景透明；若無法透明則純色簡潔背景。不要文字、標誌、浮水印、武器、魔法光效、華麗盔甲、誇張飾品、第二個人物或複雜背景。

**表情變體追加描述：**
- 中性：自然放鬆，專注聆聽，不露齒微笑。
- 擔心：眉頭輕微收緊，視線看向調查現場，不誇張驚恐。
- 放心／認同：表情稍微放鬆，嘴角輕微上揚，不做誇張歡呼。

**一致性負面限制：**

> 不要改變角色身份、年齡、臉型、髮型、髮色、服裝設計、主色、固定配件、鏡頭距離或畫風；不要新增人物、文字、浮水印、發光眼睛、魔法符文、武器、皇冠或高科技裝甲；不要將角色畫成不同人。

若圖片生成工具支援參考圖，後續表情圖應以基礎立繪作參考。若不支援參考圖，優先只使用一張基礎立繪，不要耗費大量時間追求不穩定的差分。

### 9.4 角色圖像規格與檔案格式

- 優先格式：WebP；若透明背景或工具不支援，使用 PNG。
- 建議尺寸：基礎立繪長邊 1024 px 左右；實際顯示尺寸由 CSS 控制。
- 透明背景不是硬性阻擋條件；不能透明就用單色背景或不使用立繪。
- 不要求逐像素修圖。若有白邊、去背錯誤或臉部不一致，回退到較小顯示尺寸、單張圖或純文字。
- 表情變體使用相同畫布比例，避免對話時角色跳動。
- 角色圖片只負責視覺；名稱、台詞、選項和情緒標記由資料與 UI 管理。

## 11. 第一章角色對話與狀態連動

第一章只需要少量狀態，不應建置大型角色好感系統。

### 11.1 必要敘事狀態

- `record_handling`：玩家對異常記錄的處理方式（例如封存原件或分享標註摘要）。實際枚舉值以 `06_JSON_SCHEMA.md` 定案。
- `hetin_trust_tone`：若玩法需要，可用少量敘事標籤描述禾汀的回應差異；不要求獨立數值。
- `chapter_01_complete`：第一章完成旗標；具體格式以技術文件為準。

### 11.2 選擇影響

- **封存原始碎片**：禾汀認為玩家謹慎；線索簿保存完整讀取摘要；後續角色可要求額外的來源驗證。不能因此封鎖主線或阻止瑟嵐聯絡管道出現。
- **分享標註摘要**：禾汀較願意提供地方脈絡；瑟嵐可較早注意到異常；玩家必須明確註記摘要有缺漏。不能因此讓全世界自動相信記錄。
- **不論選擇如何**：異常記錄碎片都會保留；玩家都能知道下一個驗證方向；不直接決定最終結局。

### 11.3 對話資料規則

- 對話中的角色名稱必須對應角色 ID，不能只靠顯示名稱做邏輯判斷。
- 不在台詞字串內寫入程式狀態；選擇結果由資料欄位處理。
- 角色尚不知道的秘密不可放進玩家可閱讀的台詞、替代文字、提示或 UI 標籤中。
- 每一條關鍵台詞都要能回答：說話者為什麼知道這件事？其來源是親歷、工作知識、文件、傳聞還是推測？

## 14. 角色一致性檢查表

每次新增對話、生成角色圖片、改動角色資料或調整章節時，逐項檢查。

### 14.1 身分與資訊

- [ ] 每個角色都有唯一、穩定的 `char_*` ID。
- [ ] JSON、對話、事件與場景引用同一 ID。
- [ ] 顯示名稱變更不會改變角色 ID。
- [ ] 每句關鍵台詞都有合理的資訊來源。
- [ ] 第一章未讓角色直接說出第一次界潮或空白年的完整真相。
- [ ] 灰鐘台維護殘響沒有被寫成靈魂、全知 AI 或完整事件回放。
- [ ] 玩家角色沒有無根據的預言、血統、超能力或古代記憶。
- [ ] 勢力代表沒有被簡化成只會說謊或只代表善惡的符號。

### 14.2 外觀一致性

- [ ] 同一角色所有圖片保持相同臉型、髮型、年齡感與主要服裝。
- [ ] 禾汀維持灰藍／海藻綠／褪色赭色的實用沿岸工作服。
- [ ] 禾汀的固定岸標工具或短繩扣位置與外形一致。
- [ ] 表情差分只改變表情，不無意改變衣服、鏡頭或角色身分。
- [ ] 角色圖沒有文字、浮水印、簽名或錯誤標誌。
- [ ] 若無法穩定生成一致差分，已回退為單張基礎立繪。
- [ ] 所有圖片在手機小尺寸下仍能辨識輪廓。

### 14.3 製作與檔案

- [ ] 第一章最多只有一位需要立繪的當代 NPC。
- [ ] 每個素材使用規定的角色 ID 與變體檔名。
- [ ] 尚未出場的角色沒有被列為第一章必要素材。
- [ ] 角色圖片不包含遊戲 UI；對話框、名稱和文字由程式呈現。
- [ ] 不依賴去背、手動修圖、逐格動畫或付費外部服務才能通關。
- [ ] 缺少可選圖片時，遊戲可使用文字或場景圖正常運作。

### 14.4 關係與選擇

- [ ] 角色的態度變化有具體事件或玩家行動作為原因。
- [ ] 單一選擇不會無故使角色知道未公開的秘密。
- [ ] 玩家選擇改變回應、資訊流通或後續條件，而非任意封鎖主線。
- [ ] 沒有用角色好感度取代所有複雜的信任關係。
- [ ] 每個重大角色衝突都有可理解的利益、風險或方法差異。

## 15. 與其他正式文件的同步規則

1. `01_WORLD_BIBLE.md` 決定世界規則、勢力名稱與歷史因果；本文件不得推翻其定案。
2. `02_STORY_BIBLE.md` 決定主線事件與揭露節奏；本文件補足角色動機和資訊邊界。

4. `06_JSON_SCHEMA.md` 決定角色、對話、狀態的正式資料結構；不可讓本文件的示例欄位和正式 schema 長期不一致。
5. `07_ART_BIBLE.md` 決定整體畫風；本文件的角色外觀規格應符合它。
6. `08_TECH_SPEC.md` 決定素材載入、缺圖回退與對話呈現方式。
7. 若發生衝突，先記錄衝突項目，再同步修訂相關文件；不得只改某一段台詞或提示詞而留下多份互相矛盾的設定。
