# 規格修訂補遺（2026-10-22）—直接操控與探索玩法

> **[已確認]** 核心方向；**[既有原型]** 點擊熱點互動；**[待開發]** 尚未實作；**[待決]** 數值細節未定。與舊文衝突時以本節為準。

## 核心循環
玩家直接操控單一主角在俯視／等角 2.5D 空間移動 → 觀察路徑與環境差異 → 接近並互動 → 取得線索或觸發世界狀態變更 → 利用新狀態開啟路徑／發現秘密 → 回頭驗證線索或探索新區域。場景與相機共同呈現周邊空間，不以單張背景上的熱點切換作為主要移動。

## 系統預期
1. **角色移動 [待開發]**：玩家可持續控制角色移動，方向映射一致，阻擋區域不可穿越。速度、加速度、慣性、對角線正規化、動畫與碰撞箱均為**[待決]**。
2. **探索與鏡頭 [待開發]**：鏡頭跟隨角色並顯示初始視窗外場景；邊界避免露出無效空白。平滑度、死區、前方偏移及縮放為**[待決]**。
3. **環境互動 [待開發／既有原型須查證]**：角色接近、點選物件或使用明確互動控制觸發事件；輸入模式待決。互動需有提示、成功／失敗回饋與重複觸發規則。熱區可比可見物件大，但不可取代自由移動。
4. **線索 [待開發]**：重要發現以穩定 ID 記錄，區分客觀證據、來源記載與推測。MVP 可先以簡單訊息驗證，不要求完整線索簿。
5. **秘密 [待開發]**：透過觀察、路徑、物件或狀態條件發現；給予清楚回饋並避免重複發放。
6. **環境謎題 [待開發]**：至少一個謎題需由玩家行動改變明確世界狀態，例如啟動機關或開啟通路；條件、效果及回饋需可驗證。
7. **場景轉換 [待開發]**：由出口、區域或事件觸發，保留目標場景與出生點；不要求大型無縫世界。
8. **未來戰鬥 [後續規劃／待決]**：單主角、即時、偏策略性。戰鬥數值、敵人 AI、傷害、資源、裝備及成長系統不得加入 MVP 或在此定案。

## 原型現況與驗收
- **[既有原型，待程式檢查]** 專案可能已有場景資料、文字及點擊熱點流程；不能等同直接操控 2.5D 遊戲。
- **[待開發]** 移動、碰撞、跟隨鏡頭、延伸場景、觸控移動、接近互動及謎題狀態變更，除非有程式與實測證據，否則不得視為完成。
- 每項功能分別標記「待開發／待測試／已驗證」。文件或程式提交不等於遊戲功能通過。

## 1. 核心遊戲循環

### 1.1 玩家循環

1. **進入遊戲**：顯示標題畫面，提供「繼續調查」「開始新調查」「設定」；沒有有效存檔時停用或隱藏繼續按鈕。
2. **確認目標**：場景畫面以簡短文字顯示目前主要目標；任務面板可展開查看步驟。
3. **觀察場景**：玩家閱讀背景、環境文字、角色和可互動熱點的視覺提示。
4. **調查或交談**：點擊熱點後顯示描述、對話、物件檢視或可用選項；必要互動可更新狀態。
5. **獲得回饋**：以文字、圖示、線索簿新增項目、任務更新或出口解鎖明確表示結果。
6. **選擇下一步**：玩家調查其他熱點、使用允許的道具、查看地圖或前往已開放出口。
7. **檢查事件條件**：事件系統判斷前置旗標是否齊全，符合才觸發；同一個一次性事件不得重複發獎或重複推進劇情。
8. **保存進度**：重要進展後立即嘗試寫入本機存檔；頁面離開或隱藏時可再做一次最佳努力保存，但不能只靠離開事件保存。
9. **完成章節**：必要條件全部成立時顯示章末摘要、已知事實與下一個調查方向。

### 1.2 輸入、輸出與失敗情況

- **輸入**：點擊／觸控、鍵盤輸入、玩家選項、讀取的 JSON、已保存狀態。
- **輸出**：目前場景、互動面板、任務／線索更新、道具狀態、劇情旗標、存檔結果與提示訊息。
- **資料需求**：場景資料、熱點資料、對話資料、任務資料、物件資料、旗標與存檔狀態。
- **失敗情況**：資料不存在、前置條件不成立、存檔不可用、重複點擊、離線或圖片載入失敗。
- **處理原則**：提供可理解的文字提示和可恢復操作；不能因非必要圖片或可選互動失敗而阻斷主線。

### 1.3 操作回饋原則

每次有效互動至少產生一種可觀察回饋：文字變化、熱點狀態變化、任務／線索更新、出口出現、物件狀態變更或清楚的失敗原因。單純播放裝飾效果不算完成必要互動。

## 2. 環境互動與熱點系統（角色移動為主要探索方式）

### 2.1 場景呈現

場景由世界區域、可延伸的地面／背景圖層、主角、碰撞邊界、互動物件、出口及 UI 覆層組成。主角直接移動，鏡頭跟隨角色；玩家以移動探索空間，並在接近物件或使用互動控制時觸發互動。熱點僅作互動區域或 UI 輔助，不再用點擊熱點取代自由移動。

- 背景圖片是敘事輔助，不得把必要線索只藏在難以辨識的像素裡。
- 熱點應有可點擊區域、可讀標籤或點擊後說明；觸控區域建議至少約 44×44 CSS px。
- 熱點座標使用相對百分比或明確的容器定位，避免依賴固定螢幕像素。
- 可使用「尚未調查」「已調查」「目前不可用」三種視覺狀態。不可用狀態必須有原因，不應看起來像壞掉的按鈕。
- 熱點重疊時，優先確保主要互動能被點到；裝飾熱點不可遮擋必要熱點。

### 2.2 熱點行為類型

| 類型 | 行為 | 範例 |
|---|---|---|
| `inspect` | 顯示物件描述；可首次調查後設旗標 | 無指針鐘、被刮除的銘牌 |
| `talk` | 開啟角色對話 | 禾汀 |
| `interact` | 檢查前置條件後執行動作 | 手動隔離裝置 |
| `pickup` | 取得可持有道具；需有容量／重複取得規則 | 校準片、記錄碎片（若定義為道具） |
| `read` | 打開可閱讀文件或殘響文字 | 記錄室殘響 |
| `exit` | 檢查出口條件並切換場景 | 潮痕灘前往灰鐘台 |
| `event` | 要求事件系統檢查條件；不得直接任意改寫狀態 | 讀取器首次啟動 |

一個熱點可串接多個簡單步驟，但必須保持資料可讀；避免把所有劇情寫成無法拆分的超長 JavaScript 函式。

### 2.3 點擊流程

1. 玩家點擊熱點。
2. 系統確認熱點存在、已啟用且不被對話或設定面板鎖定。
3. 檢查 `conditions`；若不符合，顯示 `blockedText` 或對應提示。
4. 執行對應的互動內容或開啟對話面板。
5. 玩家完成閱讀／選項後，才提交該互動的狀態變更。
6. 更新畫面、任務、線索簿和存檔。

必要互動應防止連續點擊造成重複執行。開啟對話期間，背景熱點暫時不可操作；關閉面板後恢復。

### 2.4 輸入／輸出／失敗

- **輸入**：場景 ID、熱點 ID、目前旗標、玩家點擊。
- **輸出**：互動面板、旗標變更、任務更新或出口狀態。
- **資料需求**：`hotspotId`、`type`、`label`、`conditions`、`blockedText`、`actions` 或對話 ID。
- **失敗情況**：找不到熱點、條件不符、資料引用不存在。
- **處理**：記錄開發期錯誤並向玩家顯示中性提示，例如「目前還無法操作」；不得讓錯誤停止整個遊戲。

## 3. 對話、選項與分支系統

### 3.1 對話呈現

對話面板顯示說話者、文字和「繼續」操作；可選擇是否顯示角色肖像。沒有肖像時仍須顯示說話者名稱。短對話可逐段顯示；文字速度設為瞬間時直接顯示完整句子。

玩家可點擊「繼續」或按 Enter／Space 推進；點擊對話文字可將當前句立即顯示完整，但不應同時跳過尚未讀取的下一句。觸控和鍵盤均須有清楚的焦點與可操作狀態。

### 3.2 選項規則

- 選項以資料定義，不能用選項顯示文字作為狀態 ID。
- 每個選項有穩定 ID、顯示文字、前置條件、執行動作和後續節點。
- 不滿足條件的選項應隱藏或停用；若隱藏會令玩家不知道有可解鎖內容，應以短提示說明需要什麼。
- 每個重大選擇必須在劇情文件說明影響；程式中只改變明確列出的旗標或資料。
- 主要劇情選擇不得永久阻斷必要線索或主線出口。若玩家採取保守選項，應提供成本較低的替代驗證路徑。
- 第一章資料處理選擇只使用 `record_handling`，合法值為 `sealed`、`summary_shared`、`location_only`。
- 對應選項／事件：`choice_ch01_archive` → `evt_ch01_choose_archive`；`choice_ch01_share_summary` → `evt_ch01_choose_share_summary`；`choice_ch01_location_only` → `evt_ch01_choose_location_only`。
- 三種選擇均保留 CL-05、CL-06 與線索簿摘要，均可完成章節；只改變處理註記與符合角色知識範圍的短回應。/

### 3.3 分支的簡化方案

第一版使用「共同主線＋少量旗標差異」，不複製整條劇情樹。選擇後回到共同主線節點，但在日誌、角色對話或後續可見資訊中反映決策。只為真正改變玩家資訊、資源或關係的選擇建立旗標；不為每句禮貌對話建立旗標。

### 3.4 輸入／輸出／失敗

- **輸入**：對話 ID、節點 ID、選項 ID、目前旗標。
- **輸出**：下一段對話、旗標更新、物品或任務變更。
- **資料需求**：節點、說話者、文字、選項、條件、動作和下一節點。
- **失敗情況**：節點不存在、選項已失效、資料形成循環、玩家重複提交。
- **處理**：阻止重複提交；若節點引用缺失，提供「返回場景」的安全出口並在開發日誌標記錯誤。

## 4. 道具與可檢視物件

### 4.1 區分三種資料

1. **背包道具**：玩家持有、可在允許條件下使用或消耗的物品。
2. **線索／文件**：玩家已發現的知識紀錄，通常永久保留，不應要求玩家消耗。
3. **場景物件狀態**：世界中的機械、門、標記或裝置狀態，例如隔離裝置是否已啟用。

不可把所有線索都塞進背包。第一章的「異常記錄碎片」至少必須是線索簿中的永久條目；若同時提供可攜帶副本，副本也不得是主線完成的唯一依據。

### 4.2 道具操作

- **取得**：滿足熱點條件後加入背包；首次取得才觸發一次性事件。
- **查看**：顯示名稱、描述、取得來源和已知用途；查看本身不消耗。
- **使用**：只能用在明確允許的目標上。可從背包選道具，再選目標；也可在特定熱點顯示「使用道具」。
- **消耗**：只有資料明確標示 `consumable: true` 且使用動作成功時才消耗。失敗的使用嘗試不得消耗。
- **重複取得**：預設不允許重複增加唯一道具；可顯示「已經記錄」。
- **關鍵物件**：主線必需的記錄和關鍵知識優先採用旗標／線索紀錄，不設背包容量限制。
- **第一章原則**：不需要複雜合成、裝備、耐久度、貨幣或戰鬥道具系統。

### 4.3 輸入／輸出／失敗

- **輸入**：道具 ID、目標 ID、條件和使用方式。
- **輸出**：物品數量／持有狀態、目標狀態、文字回饋與旗標更新。
- **資料需求**：道具 ID、名稱、描述、是否可消耗、可用目標與成功／失敗訊息。
- **失敗情況**：道具不存在、不持有、目標不相容、已使用、動作前置條件不符。
- **處理**：顯示具體但不洩漏答案的提示；失敗時不扣除道具、不改變世界狀態。

## 5. 任務追蹤與完成條件

### 5.1 任務類型與顯示

第一版使用兩類任務：

- **主線任務**：推進章節所需；介面顯示目前一個主要目標和可展開的步驟。
- **可選委託**：提供地方回饋，不阻止主線完成。第一章最多一條：「找回岸標記錄」。

任務狀態限定為 `inactive`、`active`、`completed`、`failed`。第一章不使用可逆的失敗狀態來懲罰玩家；可選委託若錯過時機，應可回頭完成或標記為未完成，不影響主線。

### 5.2 任務完成判定

任務完成由明確條件決定，而不是由玩家看到某段文字就直接完成。條件可以是「已調查熱點」「已取得線索」「已設定選擇」「已訪問場景」等旗標組合。每個任務至少定義：

- 任務 ID、名稱、簡述與類型。
- 開始條件。
- 一個或多個步驟與步驟完成條件。
- 完成條件。
- 完成後的回饋與下一任務。
- 失敗／不可完成時的替代路徑（若適用）。

### 5.3 第一章完成條件

第一章只有在以下條件全部成立時才能標記完成：

- 已訪問 `ch01_tide_mark`、`ch01_grey_bell`、`ch01_record_room`。
- 已完成潮痕灘的必要測量互動。
- 已完成灰鐘台的必要調查與安全進入步驟。
- 已取得 `item_anomaly_fragment`，並在同一取得流程中解鎖 CL-05「殘響資料不完整」與 CL-06「異常日期」。
- 已設定 `record_handling` 的有效值。
- 已將異常記錄加入線索簿並顯示章末摘要。
- 已顯示下一步可驗證方向。

可選委託、裝飾熱點和全部對話不是章節完成的必要條件。

### 5.4 輸入／輸出／失敗

- **輸入**：任務定義、旗標、線索與場景訪問記錄。
- **輸出**：任務清單、當前步驟、完成狀態與提示。
- **資料需求**：任務 ID、條件表達、步驟順序、完成訊息。
- **失敗情況**：條件缺漏、任務狀態重複變更、主線目標不顯示。
- **處理**：任務更新採冪等方式（相同事件重複收到不會重複發獎）；主線任務永遠可從任務面板重新查看。

## 6. 劇情旗標與事件觸發

### 6.1 狀態分類

- **布林旗標**：事件是否完成，例如 `ch01_measured_tide`。
- **列舉值**：有限選擇，例如 `record_handling`。
- **集合**：已取得線索、已訪問場景、已讀取文件等唯一 ID 集合。
- **場景狀態**：門、隔離器、讀取器等是否已改變。
- **設定值**：音量、文字速度、減少動態等；設定不屬於劇情進度。

旗標名稱是內部識別碼，顯示給玩家的文字應另外定義。不要將敘事文字本身存為邏輯判斷條件。

### 6.2 第一章建議旗標

| 旗標／狀態 | 型別 | 何時設定 |
|---|---|---|
| `visited_ch01_tide_mark` | boolean | 首次進入潮痕灘 |
| `ch01_measured_tide` | boolean | 完成必要測量 |
| `talked_to_hetin` | boolean | 完成禾汀的必要提醒對話 |
| `visited_ch01_grey_bell` | boolean | 首次進入灰鐘台 |
| `inspected_pointerless_clock` | boolean | 調查無指針鐘 |
| `inspected_three_arcs` | boolean | 調查三道未封合圓弧 |
| `ch01_isolation_enabled` | boolean | 正確啟用手動隔離 |
| `visited_ch01_record_room` | boolean | 安全進入記錄室 |
| `ch01_echo_read` | boolean | 完成低功率讀取 |
| `clue_anomalous_record_found` | boolean | 異常記錄加入線索簿 |
| `record_handling` | enum | 玩家確認資料處理方式 |
| `side_shore_marker_status` | enum | 可選委託狀態 |
| `chapter_01_complete` | boolean | 所有章節必要條件成立 |

實際欄位可在 `06_JSON_SCHEMA.md` 建立時調整命名，但須維持唯一、穩定且跨文件一致。

### 6.3 事件條件規則

事件定義至少包含 `eventId`、`conditions`、`actions`、`once`。條件僅允許有限、可檢查的操作：旗標相等、集合包含 ID、場景訪問、任務狀態或道具持有狀態。第一版不要執行來自 JSON 的任意 JavaScript，也不要使用 `eval`。

事件動作採固定白名單，例如：設定旗標、加入線索、取得道具、更新任務、開啟出口、顯示訊息、完成章節。一次性事件先檢查是否已執行，再提交狀態更新；若存檔失敗，遊戲仍須能在本次工作階段繼續，但要提示保存可能失敗。

### 6.4 輸入／輸出／失敗

- **輸入**：目前狀態、事件定義、互動結果。
- **輸出**：符合條件的事件動作、更新後狀態。
- **資料需求**：事件 ID、條件、白名單動作、一次性設定。
- **失敗情況**：未知條件運算子、未知動作、事件循環或重複觸發。
- **處理**：拒絕未知動作並記錄錯誤；事件鏈須有上限或去重機制，避免同一事件在一個更新循環內無限觸發。

## 7. 地圖、出口與場景切換

### 7.1 第一版地圖

第一版使用簡單的「已知地點列表／章節路線圖」，不製作可縮放的大地圖。地圖顯示玩家已知或已造訪的地點；未解鎖地點可以顯示為未知，但不能讓玩家點入。場景出口同時可直接呈現在場景內。

第一章路線：

`ch01_tide_mark` ⇄ `ch01_grey_bell` ⇄ `ch01_record_room`

方向是否開放由場景出口資料決定。回訪已開放場景時保留已取得線索、已完成互動和裝置狀態。必要路線不能只靠難以辨識的背景像素提示。

### 7.2 場景切換流程

1. 玩家點擊出口或地圖中的已開放地點。
2. 系統檢查出口條件；若不符合，顯示原因或下一個必要目標。
3. 儲存當前場景狀態與玩家進度。
4. 設定新的場景 ID，載入其資料與背景。
5. 還原該場景的互動狀態，更新任務目標。
6. 將焦點移到新場景標題或主要內容，讓鍵盤與螢幕閱讀使用者知道位置已變更。

場景切換可使用短淡入淡出；效果失敗或低動態模式開啟時，直接切換。不要使用必須載入外部影片或大型動畫才能完成的轉場。

### 7.3 輸入／輸出／失敗

- **輸入**：目前場景 ID、出口 ID、目的場景 ID、解鎖條件。
- **輸出**：新場景、場景標題、更新的訪問紀錄與任務。
- **資料需求**：場景 ID、出口目標、條件、顯示標籤。
- **失敗情況**：目的場景不存在、出口被鎖定、背景載入失敗。
- **處理**：保留目前場景並顯示原因；若只是背景失敗，使用純色背景和場景文字繼續遊玩。

## 8. 玩家進度與本機存檔

### 8.1 儲存方案

**[必須]** 第一版使用瀏覽器 `localStorage` 儲存少量 JSON 進度與設定，不建立帳號、不上傳雲端。存檔只屬於目前瀏覽器／裝置；清除網站資料、使用無痕模式或更換裝置可能遺失。遊戲啟動前必須確認目前瀏覽器可用，不得假設所有瀏覽器都允許儲存。

建議採單一版本化存檔鍵，例如 `unwritten_world_save_v1`。資料包括：

- `saveVersion`：存檔格式版本。
- `updatedAt`：最後保存時間（只作資訊，不依賴它判斷劇情）。
- `currentSceneId`：目前場景。
- `flags`：劇情旗標。
- `visitedScenes`：已訪問場景 ID。
- `clues`：已取得線索 ID 集合。
- `inventory`：持有道具與數量。
- `quests`：任務狀態。
- `sceneStates`：需保留的裝置與互動狀態。
- `settings`：玩家偏好。

### 8.2 何時保存

- 進度改變後（取得線索、完成任務、確認重大選擇、切換場景）立即嘗試保存。
- 設定變更時保存設定。
- `visibilitychange` 或頁面離開時可額外嘗試保存，但這是補強，不是唯一保存時機。
- 避免每次逐字動畫更新都寫入存檔；只在有意義的狀態變更時保存。

### 8.3 載入與損壞處理

1. 讀取存檔字串；不存在時建立新遊戲預設狀態。
2. JSON 解析失敗時不讓整個遊戲白屏；告知玩家存檔無法讀取，提供「以新調查開始」並保留原始資料不被默默覆蓋。
3. 驗證版本、欄位型別、場景 ID 和 ID 集合；丟棄未知欄位可作相容策略，但不得讓錯誤資料觸發事件。
4. 舊版本存檔可用明確遷移函式處理；若未定義遷移，提供清楚提示，不可默默錯誤套用。
5. `localStorage.setItem` 失敗時顯示「本次遊玩仍可繼續，但進度可能無法保存」，不要反覆彈出提示。
6. 清除／重新開始必須二次確認；不得把清除設定與重置劇情進度混成一個無提示操作。

### 8.4 手動匯出／匯入

**[後續可選]** 可加入純文字 JSON 存檔匯出／匯入，便於換裝置；不是第一章上線或核心通關的必要條件。匯入時必須驗證資料格式和版本，錯誤檔案不得覆蓋目前有效存檔。

### 8.5 輸入／輸出／失敗

- **輸入**：目前狀態物件、存檔字串。
- **輸出**：已還原狀態、保存成功／失敗提示。
- **資料需求**：版本化 JSON 結構與預設狀態。
- **失敗情況**：儲存空間不可用、JSON 損壞、版本不相容、配額不足。
- **處理**：使用記憶體中的狀態繼續遊玩，清楚提示持久保存受限；絕不宣稱已保存成功。

## 9. 設定選單與偏好

### 9.1 第一版設定

| 設定 | 預設 | 行為 |
|---|---|---|
| 音效 | 開／低音量（若有音效） | 若沒有音效資產，提供靜音／音效開關不應偽裝成有效音量控制 |
| 音樂 | 開／低音量（若有音樂） | 不需要第一章一定有背景音樂；不播放自動音訊也可完整遊玩 |
| 主音量 | 70%（僅當實際音訊存在） | 使用滑桿控制音量；無音訊時隱藏或標示尚未提供 |
| 文字速度 | 中 | 慢／中／快／立即顯示；影響對話逐字顯示，不影響任務狀態 |
| 文字大小 | 標準 | 小／標準／大；透過 CSS 變數套用，避免破版 |
| 動態效果 | 標準 | 標準／減少動態；減少動態停用非必要轉場與呼吸動畫 |
| 高對比 | 關 | 開啟更明顯的文字、按鈕和熱點邊界 |
| 介面方向提示 | 自動 | 提示可旋轉，但不得強迫鎖定裝置方向 |
| 文字顯示 | 一般 | 確保重要文字不只依賴顏色傳達 |

設定可以存在於同一個設定面板；在手機上使用可滾動面板，不要求另外製作複雜的設定場景。

### 9.2 音訊限制

瀏覽器可能要求使用者先點擊後才允許播放音訊。若音訊播放被阻擋，遊戲仍須正常開始，並在需要時提供明確的「啟用音效」按鈕。核心劇情資訊不得只靠音效傳遞。音量控制只在有實際音訊時出現或啟用。

### 9.3 輸入／輸出／失敗

- **輸入**：玩家設定變更。
- **輸出**：立即套用的視覺／音訊偏好與保存的設定。
- **資料需求**：受允許值約束的設定物件。
- **失敗情況**：未知設定值、存檔失敗、瀏覽器阻擋音訊。
- **處理**：使用安全預設值；設定面板仍可操作；不影響劇情進度。

## 10. 手機直向、橫向與響應式介面

### 10.1 原則

- **手機直向**是第一優先版面。
- 橫向、平板與桌面需可操作，但不要求像原生遊戲一樣鎖定方向。
- 以 CSS Grid/Flexbox、相對單位、`max-width` 和媒體查詢調整；避免以裝置型號做判斷。
- 主要內容需尊重安全區域（例如瀏海／底部手勢區），並確保頁面不被瀏覽器工具列遮住。
- 文字面板可滾動，按鈕不應因鍵盤出現或視窗高度縮小而消失。

### 10.2 直向版面

建議順序：頂部狀態列／場景標題 → 場景圖片與熱點 → 目前目標／快速工具 → 底部操作列。對話面板可從底部展開，場景仍保留足夠上下文；必要時以遮罩保護對話操作。任務、地圖、線索簿和背包採抽屜或獨立面板，不要同時全部展開。

### 10.3 橫向版面

採左右分區：主要場景區佔大部分寬度，任務／互動資訊區佔較窄側欄；小螢幕橫向時側欄可改為可收合面板。不得只因橫向就把文字縮得很小。旋轉裝置後應保留目前場景、對話位置和玩家進度。

### 10.4 熱點與觸控

- 互動區至少約 44×44 CSS px；若背景熱點較小，使用較大的透明點擊區。
- 不以 hover 作為唯一提示；觸控裝置沒有穩定 hover。
- 點擊後應立即顯示已選取狀態，避免玩家重複點擊。
- 滾動面板內的按鈕與場景熱點不可重疊；可拖曳／滑動區域不可意外觸發點擊。
- 重要按鈕避免緊貼螢幕邊緣，並提供文字標籤而不只使用圖示。

### 10.5 輸入／輸出／失敗

- **輸入**：視窗尺寸、方向、觸控或滑鼠操作。
- **輸出**：重新排版但不重置遊戲狀態。
- **資料需求**：CSS 斷點、容器比例、可收合面板狀態。
- **失敗情況**：旋轉後面板溢出、按鈕被遮擋、熱點偏移。
- **處理**：允許面板內滾動；背景使用容器尺寸定位；方向變更後重新計算熱點位置，不重新載入劇情。

### 11.1 預設操作表

| 動作 | 觸控／滑鼠 | 鍵盤 |

### 11.2 鍵盤規則

- 所有可互動元素使用原生按鈕或具備等效語意的可聚焦控制項。

### 11.3 輸入／輸出／失敗

- **輸入**：點擊、觸控、鍵盤焦點與按鍵。
- **輸出**：同一套遊戲狀態變更，不因輸入裝置不同而改變結果。
- **資料需求**：按鈕標籤、焦點順序、面板狀態。
- **失敗情況**：焦點遺失、連續觸發、觸控被判為滾動。
- **處理**：鎖定正在處理的互動直到完成；使用原生控制項與足夠點擊區；必要操作提供可見按鈕作備援。

## 12. 新手引導與錯誤提示

### 12.1 漸進式引導

只在玩家第一次遇到對應系統時顯示簡短提示，可關閉且不阻斷操作：

1. **潮痕灘**：「點擊場景中有標記的物件來調查。」
2. 首次取得線索：「線索已加入線索簿；你可以隨時重新查看。」
3. 首次出現出口：「完成目前必要調查後，可使用出口前往下一處。」
4. 首次重大選擇：「選擇會記錄在調查日誌；必要主線不會因一次選擇永久中斷。」
5. 首次存檔失敗：「本次仍可繼續，但進度可能無法保存。」

引導是否顯示可以使用設定旗標保存；若無法保存，引導重複出現也不得阻止遊玩。

### 12.2 錯誤訊息原則

錯誤訊息應告訴玩家「發生什麼、可以做什麼」，不暴露堆疊追蹤或程式內部資料。

| 情況 | 玩家訊息／處理 |
|---|---|
| 尚未滿足互動條件 | 說明目前缺少的線索或步驟 |
| 道具不能用在此處 | 「這件物品目前沒有可用的對應位置。」 |
| 場景資料無法載入 | 顯示場景名稱與文字備援；提供返回或重試 |
| 存檔不可用 | 說明本次進度可能無法保留，允許繼續 |
| 未知的存檔版本 | 提示不相容，不默默覆蓋舊資料 |
| 必要內容資料缺漏 | 對玩家顯示可理解的備援頁；開發期記錄具體 ID |
| 重複點擊 | 忽略重複輸入，不重複發獎或推進事件 |

## 13. 離線友善與資源載入

### 13.1 基本離線原則

- 遊戲內容以本地 HTML、CSS、JavaScript、JSON 與靜態圖片提供；核心流程不呼叫遊戲運行時 AI API 或自有後端。
- GitHub Pages 首次載入仍需要網路。**未實作 Service Worker 前，不得宣稱關閉網路後可重新開啟遊戲。**
- 即使背景圖缺失，必要文字、互動、線索與任務仍能繼續。
- 不使用外部字型、追蹤腳本、遠端影音或第三方 API 作為核心流程依賴。
- 遊戲可在資源已載入的當次工作階段繼續遊玩，即使之後暫時斷線；存檔仍受瀏覽器儲存能力限制。

### 13.2 可選離線快取（後續）

**[後續]** 如需可離線重新開啟，可使用 Service Worker 快取版本化的應用殼、必要 JSON、CSS、JavaScript 和小型圖片。此功能須獨立測試快取更新、舊版本清除、首次離線啟動、GitHub Pages 子路徑和快取空間不足。不得讓快取失敗阻止線上正常遊玩。

### 13.3 資源失敗與降級

- 背景圖片失敗：顯示純色或漸層背景、場景標題和互動清單。
- 非必要裝飾圖片失敗：隱藏該圖片，不顯示破圖圖示。
- JSON 資料失敗：若是必要場景，顯示簡單錯誤頁並提供重試／返回；不得把錯誤資料套入狀態。
- 音訊失敗：靜音運行。
- 儲存失敗：以記憶體狀態繼續當次遊玩，提示進度可能遺失。
- 外部服務不可用：核心玩法不受影響，因第一版根本不依賴外部服務。

## 14. 無外部服務時的降級方案

| 能力 | 預設實作 | 失敗／缺少時的降級 |
|---|---|---|
| 劇情文字 | 本地 JSON | 內建最小錯誤提示，不依賴遠端取回 |
| 場景圖片 | 專案內靜態檔案 | 純色背景＋文字場景 |
| 音效／音樂 | 可選本地資產 | 完整靜音遊玩 |
| 存檔 | localStorage | 記憶體遊玩＋明確警告 |
| 地圖 | 本地場景連接資料 | 顯示已開放地點清單 |
| 字型 | 系統字型 | 使用系統預設字型 |
| AI 內容生成 | 開發製作階段可使用外部 AI | 發布後所有必要內容均已包含於專案；運行時不呼叫 AI |
| 分析／遙測 | 不使用 | 不需要替代服務 |
| 登入／雲端同步 | 不使用 | 以裝置本機進度為準 |

## 15. 最小資料模型與邏輯邊界

本節只定義系統需要的資料概念；正式欄位型別、必填欄位與 JSON 範例由 `06_JSON_SCHEMA.md` 統一。

### 15.1 場景資料

至少包含：`sceneId`、`title`、`description`、`background`（可空）、`hotspots`、`exits`。熱點至少包含：`hotspotId`、`label`、`type`、`conditions`、`blockedText` 和對應互動內容引用。出口至少包含：`exitId`、`targetSceneId`、`label`、`conditions`。

### 15.2 對話資料

至少包含：`dialogueId`、節點 ID、說話者、文字、選項陣列。選項包含穩定 ID、顯示文字、條件、動作與下一節點。文字內容不能當作邏輯 ID。

### 15.3 狀態物件

遊戲狀態以一個可序列化的純資料物件為中心；UI 只呈現狀態，互動由受控函式修改狀態。不要在 DOM 節點上存放唯一的劇情真相，也不要讓場景資料直接執行任意程式碼。畫面重新渲染後，旗標、線索和任務必須仍可恢復。

### 15.4 邏輯白名單

允許的動作限定為明確函式：設定旗標、加入線索、取得／移除道具、更新任務、設定場景物件狀態、開啟出口、顯示文字、標記章節完成。未知動作應被拒絕並記錄開發錯誤。避免引入外部狀態管理框架或複雜事件總線。

### 16.1 發布阻擋條件

以下任一項成立，就不能把第一章標記為可發布：

- 必要場景、必要對話或主線線索缺失，造成無法完成章節。
- 任一重大選擇會永久鎖死主線。
- 重複點擊可以重複取得唯一線索或重複推進章節。
- 存檔錯誤造成白屏，或介面宣稱保存成功但實際未保存。
- 手機主要按鈕被遮住、無法觸控或文字無法閱讀。
- 只有圖片或音效載入成功才能理解必要劇情。
- 核心流程依賴登入、伺服器、遠端 AI 或第三方服務。

## 17. 第一章製作順序

為了讓免費 AI 協作和手機端維護可控，依序完成：

1. 建立最小頁面框架與響應式場景容器。
2. 建立場景資料載入與場景切換。
3. 實作熱點和必要條件檢查。
4. 實作對話面板與選項。
5. 實作旗標、線索簿與任務追蹤。
6. 完成三個場景的必要流程與章節完成判定。
7. 加入 localStorage 存檔、載入、損壞處理和重置確認。
8. 加入設定、鍵盤操作和減少動態模式。
9. 加入背景圖與可選音訊；確認資產缺失時仍可玩。
10. 依 GP-01 至 GP-25 驗收，再發布到 GitHub Pages。

每一步都應保留可運行版本；不要一次生成整個遊戲後才開始除錯。
