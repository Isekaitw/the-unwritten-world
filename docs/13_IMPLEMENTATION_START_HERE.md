# 程式開發入口與企劃一致性檢查

> 更新日期：2026-11-06。這份文件是每次程式任務的執行入口。所有改動都必須遵守原企劃方向；現有原型是可重用基礎，不是新的產品規格。

## 1. 每次程式修改前：必做比對
1. 讀取 `AGENTS.md`、`docs/12_SPEC_AUTHORITY_AND_STATUS.md`、`docs/00_PROJECT_MASTER.md`、`docs/09_CONTENT_ROADMAP.md`、`docs/11_CURRENT_GAMEPLAY_DECISIONS.md`。
2. 依改動範圍讀取對應規格：玩法讀 `03_GAMEPLAY_SPEC.md)；世界／劇情／角色讀專題聖經；場景讀 `05_SCENE_CATALOG.md`；資料讀 `06_JSON_SCHEMA.md`；美術讀 `07_ART_BIBLE.md`；技術讀 `08_TECH_SPEC.md`；測試讀 `tests/manual-test-checklist.md`。
3. 讀取目前 `main` 的實際 commit、相關程式、資料與測試；不得依賴過期路徑或舊分支快照。
4. 變更前明確列出：需求目的、對應企劃章節、現有實作、預期差異、可能衝突、受影響文件與驗收方式。
5. 若需求與已確認方向或正史衝突，先停止衝突部分並說明，不可自行改寫企劃或默默照做。可逆技術細節可採最小方案並保留既有行為。

## 2. 每次程式修改後：必做比對
1. 對照變更 diff，確認沒有擴大需求或偏離企劃。
2. 檢查程式行為是否符合對應玩法／技術／資料規格。
3. 若程式行為、檔案路徑、資料格式、數值或狀態定義改變，同步更新受影響文件與測試清單；只更新相關文件，不必每次重寫全部企劃。
4. 分開記錄靜態檢查、語法檢查、桌面瀏覽器、手機／平板、Pages 部署；未實際執行的一律標「未測試」。
5. 若本次改變現況，更新 `docs/11_CURRENT_GAMEPLAY_DECISIONS.md` 與 `docs/12_SPEC_AUTHORITY_AND_STATUS.md`；更新路線圖狀態必須附驗收證據。
6. 回報 commit SHA、修改檔案、企劃比對結果、測試環境與結果、未測項目、風險及回退方式。

## 3. 不可違反的專案方向
- 手機／平板優先、瀏覽器執行、原創 2.5D 單人探索冒險。
- 直接角色移動、環境觀察、互動、秘密、線索與狀態謎題是核心循環。
- HTML、CSS、原生 JavaScript、JSON；GitHub Pages 靜態部署；零預算；不依賴付費 API、執行時 AI API、登入或持續連線後端。
- 不擅自改動世界觀、故事、角色正史或既定第一章正式場景。
- 戰鬥維持原企劃後續方向，不因目前已有背包／角色參數／氧氣 UI 就擴張 MVP。
- 保留可重用原型；若與正式規格不一致，採最小重構，不讓臨時測試數值綁架正式設計。

## 4. 目前程式入口與已知原型
- `index.html`、`css/main.css`、`css/mvp.css`、`js/mvp.js`。
- 已有角色移動、碰撞、邊界、相機、測試區互動／秘密／機關、Canvas 視野遮罩。
- 提前存在背包、角色參數、任務 UI、氧氣消耗／恢復及 localStorage 保存／讀取。
- 正式 JSON-driven scene loader 與第一章完整資料整合尚未確認完成。
- 目前水平視野 1200 世界單位；垂直視野依視窗高度調整。

## 5. 開發階段
依 `docs/09_CONTENT_ROADMAP.md`：M0 原型驗收 → M1 技術架構穩定化 → M2 正式資料系統 → M3 第一章內容整合 → M4 第一章正式系統 → M5 發布驗收 → M6 後續內容。此順序不改變原企劃最終願景。

## 6. 基本驗收要求
- 所有修改均需有可重現的測試步驟。
- 程式提交、部署成功、語法通過與瀏覽器功能通過是不同狀態。
- 不宣稱未執行的瀏覽器、手機／平板或 Pages 測試通過。
- 若沒有可操作瀏覽器工具，明確記錄未實際瀏覽器測試，不得以靜態檢查代替。
