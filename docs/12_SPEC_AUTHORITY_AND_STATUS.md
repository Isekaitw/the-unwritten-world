# 文件權威、現行決策與專案狀態

> 更新日期：2026-11-06。本文是跨文件索引；不取代世界觀、故事、角色、美術等專題聖經。同步目前程式狀態不代表未測試功能已通過。

## 1. 不變的正式遊戲方向
- 《零界紀元：THE UNWRITTEN WORLD》是瀏覽器執行的原創 2.5D 動作探索冒險；**現階段以電腦版優先開發與驗收**，手機／平板列為次要相容性目標。
- 單人、單一主角；直接移動探索、觀察環境、接近並調查物件、收集線索、發現秘密，透過環境謎題改變世界狀態。
- HTML、CSS、原生 JavaScript、JSON；GitHub Pages 靜態部署；零預算；核心流程不依賴執行時 AI API、付費服務、登入或持續連線後端。
- 抽象借鑑探索、環境互動、解謎與秘密發現，不複製其他作品的角色、世界、美術、故事、介面或專屬內容。
- 第一章正式內容依世界觀、故事、角色及場景聖經；原定後續即時偏策略戰鬥方向保留，不提前併入 MVP。

## 2. 現階段平台優先順序
- 電腦桌面瀏覽器是主要開發、操作設計、效能分析與驗收平台；鍵盤／滑鼠為主要輸入。
- 手機／平板暫不作為主要開發與驗收阻塞條件，但保留既有觸控支援及未來相容性。
- 遊戲核心、規則與狀態共用；裝置差異只放在輸入適配及必要的呈現適配。
- 此決策只調整開發順序，不改世界觀、故事、角色正史、核心玩法或長期規劃。

## 3. 階段邊界
### A. 技術原型與驗收（目前優先）
先驗收現有測試區：角色移動、碰撞、邊界、相機、互動、秘密、狀態謎題、視野遮罩及已提前存在的 UI／狀態功能。這階段不等於第一章完成。

### B. 技術架構穩定化
整理可重用程式、狀態管理、輸入生命週期、DOM/CSS + Canvas 混合呈現及回歸測試。採增量修改，不因抽象化需求全面重寫。

### C. 正式資料系統
依 `06_JSON_SCHEMA.md` 建立正式 JSON 載入、驗證、穩定 ID 與跨場景引用；目前尚未確認正式 loader 已完成。

### D. 第一章內容整合與發布
仍以既定正式場景與原有故事／角色／世界設定為準。正式任務、線索、物品、存檔及章節流程依企劃規格整合與驗收。

### E. 後續擴充
依原企劃擴充章節及系統；戰鬥仍屬後續方向，未經正式規格與範圍確認不得提前加入 MVP。

## 4. 狀態標籤
- **已確認**：正式方向／規則已採納。
- **既有規格**：已定義且未被正式取代。
- **已有原型**：程式中存在實作，未必完整。
- **提前實作**：超出目前里程碑但程式已存在，不因此改變正式範圍。
- **待開發**：程式尚未實作。
- **待驗收**：已有程式但缺對應測試證據。
- **已驗證**：必須附 commit、日期、環境、操作步驟及結果。
- **待決／受阻**：不得自行當成定案；受阻需列原因與解除條件。

「文件寫了」不等於程式完成；「程式已提交」不等於測試通過；電腦桌面測試通過不等於 Pages 部署或手機／平板相容性通過。

## 8. 測試場景商人與交易原型補遺（2026-11-06）
- 目前單一測試場景新增測試商人、既有樣式對話、錢包、市集與三項測試商品；此為提前實作的功能原型，尚未成為正式第一章內容契約。
- 測試貨幣初始 100；購買會扣款、增加背包物品數量並記錄交易，資料隨本機即時存檔與存檔點快照保存。
- 第一章既有「不需要複雜合成、裝備、耐久度、貨幣或戰鬥道具系統」規劃不因測試原型而自動改寫；未來是否納入正式內容，需依正式企劃另行確認。


## 9. 桌面操作與背包 UI 現行補遺（2026-11-07）
- 桌面場景互動只使用 F；不以場景點擊或獨立螢幕互動按鈕觸發。E 為背包、T 為任務。
- 錢包入口位於背包標題列右上方，內容在背包內展開；不再列為獨立遊戲場景面板。
- 背包面板自身捲動，遊戲頁面不隨背包內容捲動；所有格位維持固定尺寸。
- 此為現行原型操作／UI 規則；本次程式靜態修改不代表桌面瀏覽器、Pages 或手機／平板實測通過。


## 10. 背包滿版內容區補遺（2026-11-07）
- 桌面背包需讓實際內容區滿版利用視窗寬高；只有外層覆蓋視窗、內層仍限制在約 920px 並留大片空白，不符合需求。
- 物品格與角色狀態區共同填滿主要剩餘高度；桌面版背包及主頁不出現捲動。
- 物品名稱可換行完整顯示，不使用單行省略裁切。
- 本補遺是目前原型 UI 呈現決策，不提升提前實作的背包為正式章節系統，也不代表瀏覽器實測通過。

## 11. 錢包 UI 簡化補遺（2026-11-07）
- 背包標題列只顯示目前持有的貨幣餘額，不設錢包頁面、按鈕或可展開面板。
- 不顯示交易紀錄；市集仍顯示目前持有餘額，購買流程與扣款驗證維持。
- 存檔只需保存貨幣餘額；舊版交易紀錄欄位可忽略，不需變更存檔版本。


## 12. 互動距離與高亮一致性（2026-11-07 修訂）
- 測試場景五種互動物件共用 80px 偵測半徑與同一套靠近高亮。
- 商人／存檔點的常態光暈與存檔點啟動外觀保留；靠近高亮的 CSS 優先權高於物件常態樣式，避免高亮消失。
- 此為原型互動回饋規則，不改變正式玩法契約；實際距離手感仍待瀏覽器驗收。

## 13. 任務／背包與市集鍵盤操作（2026-11-07）
- 任務與背包均使用全螢幕介面；背包內容四周保留較寬留白，避免貼邊。
- 商人對話以第二次 F 直接進入市集；市集內按 F 退出。
- 不顯示「前往市集」或「離開市集」按鈕；Esc 仍可作為替代關閉方式。


## 14. 效能優化現況（2026-11-07）
- 已加入第一輪無感優化：角色座標未變時跳過場景更新；視野遮罩在玩家座標、通路遮擋狀態及 Canvas backing resolution 均未變時重用既有繪製結果。
- 本次不改變玩家可觀察的操作與遊戲規則；不降低畫質、視野、陰影、模糊或更新反應。
- 目前只完成靜態程式層面的優化確認，尚無瀏覽器 profiler／FPS／幀時間數據；不得標示為全面效能優化已完成。


## 15. 桌面效能診斷與驗證狀態（2026-11-08）
- 已在原型加入 opt-in 效能浮層：網址加 ?perf=1 顯示平均 FPS、平均／P95 frame time、主要函式耗時、視野快取命中、射線數、DPR 與可取得時的 JS heap。
- 一般遊玩未啟用時不建立浮層、不執行量測包裝、不新增網路請求。
- 量測工具不等同完整瀏覽器 profiler，無法直接分離 GPU 時間；尚未取得瀏覽器實測數據，效能改善幅度未知。
- 目前仍是 DOM/CSS + Canvas 原型；正式的模擬／呈現／動態效果／資源生命週期邊界列為後續架構目標，不宣稱已完成模組化重構。


## 16. 視野初始化與動態效果架構（2026-11-08）
- 已調整探索啟動：等待兩個 requestAnimationFrame 後才執行第一次場景／視野計算；ResizeObserver 監測 viewport 尺寸變化並使視野快取失效。
- 角色停止時跳過靜態場景更新的既有優化仍保留；動態效果透過獨立 update/render 生命週期逐影格更新，不依賴角色移動。
- 回到標題時清理註冊效果。視野快取鍵包含玩家位置、通路狀態、Canvas backing resolution、視野半徑、亮度及霧度。
- 靜態程式已修改；首次視野視覺、ResizeObserver 行為及動態效果註冊／卸載仍需瀏覽器驗收。尚未加入實際粒子系統。
